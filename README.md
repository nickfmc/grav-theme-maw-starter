# MAW Starter (Grav 2.1 theme)

Block-based, AI-friendly starter theme for Grav 2.1 by Mountain Air Web. Pages are built from a typed block library defined in YAML, styled with design tokens, and there is no build step.

- **16 blocks** (hero, features, cards, media-text, FAQ, pricing, stats, logos, testimonials, gallery, contact, CTA, collection, embed, rich text, spacer). Each block is a blueprint, a template, and an optional CSS file.
- **Shared section settings** on every block: background presets or custom colour, spacing, width, alignment, reveal, `hidden`, and per-device `hide_on`.
- **Design tokens** in `css/tokens.css`, with `@layer` ordering and light/dark mode.
- **Agent-ready**: `bin/maw.php sync` generates `docs/ai/blocks.md` (fields plus YAML example for every block) in the site root, and `/styleguide` renders every block.
- **Visual builder contract**: the templates carry `maw_edit*()` markers, so the [MAW Builder](https://github.com/nickfmc/grav-plugin-maw-builder) plugin can edit text, Markdown, images and repeaters directly on the page. The theme works without the plugin.

## Install

New sites: use the kit (`maw.ps1 new`), which adds this theme as a git submodule.

Manually, in a Grav 2.1 site:

```bash
git submodule add https://github.com/nickfmc/grav-theme-maw-starter.git user/themes/maw-starter
php user/themes/maw-starter/bin/maw.php sync
php user/themes/maw-starter/bin/maw.php styleguide
```

Then set `pages.theme: maw-starter` in `user/config/system.yaml`. The `form` plugin is required.

## Layout

```
maw-starter.php            Twig helpers (maw_blocks, maw_media, fa_icon, maw_embed_url, maw_slug, maw_contrast, maw_visibility, maw_edit*)
maw-starter.yaml           theme defaults (brand, header, footer)
bin/maw.php                CLI: sync | new-block <type> | lint | normalize | styleguide
css/tokens.css             all design tokens (--maw-*) and the @layer order
css/blocks/<type>.css      per-block CSS, loaded only when the block is on the page
css/custom.css             project overrides (unlayered, wins)
templates/blocks/<type>.html.twig   one template per block, wrapped by _section.html.twig
blueprints/blocks/<type>.yaml       source of truth for a block (title, description, example, fields)
blueprints/blocks/_settings.yaml    shared block settings
blueprints/partials/*, blueprints/modular/*   generated by `sync`, don't edit by hand
```

## Site layer (per-site customisation)

Sites include this theme as a shared submodule, so client-specific work goes **outside** it:

| File | Effect |
|---|---|
| `user/site/css/site.css` | loaded last (after `css/custom.css`); token overrides and site rules |
| `user/site/css/blocks/<type>.css` | loaded after the theme's block CSS, only on pages using that block |
| `user/site/templates/**` | overrides any theme template by relative path (keep the `maw_edit*()` markers) |
| `user/site/js/site.js` | loaded after `js/site.js` |
| `user/config/themes/maw-starter.yaml` | brand, header and footer settings |

## Block data shape

```yaml
blocks:
  - type: features          # matches blueprints/blocks/features.yaml
    background: alt         # shared settings, flat
    hide_on: [mobile]
    features:               # content nested under the type name (the shape Admin2 reads and writes)
      heading: Why us
      items:
        - { icon: fa-bolt, title: Fast, text: No database. }
```

Templates receive `block` flattened, so write `block.heading`.

## CLI

```bash
php user/themes/maw-starter/bin/maw.php new-block team-grid   # scaffold template + blueprint + css + modular wrapper
php user/themes/maw-starter/bin/maw.php sync                  # regenerate admin field, modular blueprints, docs/ai/blocks.md
php user/themes/maw-starter/bin/maw.php styleguide            # rebuild user/pages/styleguide from block examples
php user/themes/maw-starter/bin/maw.php lint                  # validate blocks and page frontmatter
php user/themes/maw-starter/bin/maw.php normalize             # convert flat blocks to the nested shape
```

Run `sync` and `lint` after changing any `blueprints/blocks/*.yaml`.

## Rules worth knowing

- Twig 3: `items|filter(i => i.visible)`, `{% apply spaceless %}`, and `replace` takes a map.
- Import macros **inside** `{% embed %}` blocks.
- Never hard-code colours in block CSS. Use tokens, and put project changes in `css/custom.css`.
- Keep page content inside `<main id="content">` so Markdown output (`/<route>.md`) stays clean.

## Versioning

Tag releases (`vX.Y.Z`) and bump `version` in `blueprints.yaml`. Sites pin a commit through their submodule and update with `maw.ps1 update`.
